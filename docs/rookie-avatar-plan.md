# 야구선수 도트 아바타 — 분석·실행 계획

사용자 결정: 구매 에셋의 기존 비율로 먼저 연결하고 야구복·시상식 동작을 확장해요. 첨부 이미지의 트로피를 든 수상 장면을 참고하되, 첨부 인물을 복제하지 않아요.

## 구매본 확인

- 원본 위치: 사용자가 지정한 `도트디자인` 폴더. ZIP·설치 파일을 변경하거나 실행하지 않아요.
- `moderninteriors-win.zip`: Modern Interiors 정식 버전, 성인 몸·눈·의상·머리·액세서리 레이어와 `Spritesheet_animations_GUIDE.png`, 라이선스 포함.
- `Character Generator 2.0 Linux Build.zip`: 같은 캐릭터 조각과 생성 도구. 도구 실행 없이 조각을 조사할 수 있어요.
- 기본 프레임 16×32, 정수 확대·nearest-neighbor 표시. 걷기·대기·물건 들기 등 원본 동작이 있으므로 단순히 정지 그림을 흔드는 효과 대신 실제 프레임 애니메이션을 쓸 수 있어요.
- 정식 버전 라이선스는 상업/비상업 프로젝트 편집·사용을 허용하고 원본/편집 에셋의 재판매·배포를 금지하며 LimeZu 크레딧을 요구해요. 코드와 구매 원본의 라이선스는 별개예요. 원본 팩·편집 가능한 전체 라이브러리는 저장소나 다운로드 상품으로 제공하지 않고 게임에 필요한 부분만 로컬 미디어로 사용해요.

## 목표와 검증

1. 구매 에셋·애니메이션 좌표·의상 확인, 야구복/시상식 디자인 선택과 제작 기록.
2. 정식·라이트·익스트림 생성 폼에서 외형을 고르고 움직이는 미리보기. 허용 목록으로 입력 검증하며 외형은 경기 능력치·난수에 영향 없음.
3. 선택한 외형을 선수 데이터에 저장하고 새로고침·게임 진행 뒤 같은 모습 유지. 기존 선수도 안정적인 기본 모습 제공.
4. 내 선수 화면의 대기/걷기와 수상/시상식 장면의 트로피 동작 연결. 회원 공개 규칙·모드 분리 유지.
5. PC·모바일 390/320px, 키보드·동작 줄이기·JS OFF·에셋 누락 대체 화면, 실제 생성 POST와 수상 렌더 확인.
6. 조사 결과·사용 에셋/크레딧·재현 방법·추가 작화 범위 기록. 기본 DB·운영 서버·외부 메모리 미변경.

## 최종 적용

- **선수 생성**: 정식·라이트·익스트림 공용 폼에서 피부 9종, 머리 모양 6종, 머리색 3종, 유니폼 3종, 캡 3종/모자 없이 선택. 대기·걷기·수상 미리보기.
- **저장**: 정식은 `RookiePlayer.career.avatar_v1`, 라이트·익스트림은 `LiteCareer.flags.avatar_v1`. 생성과 외형 저장을 같은 트랜잭션으로 처리해요. 기존 선수는 ID로 정해지는 기본 외형을 표시하며 DB를 새로 쓰지 않아요.
- **플레이**: 정식 선수 카드·공개 선수 페이지, 라이트·익스트림 상단 HUD. 모바일 HUD가 설명 `span`을 숨기는 기존 규칙에 아바타가 휩쓸리지 않도록 전용 범위를 명시했어요.
- **수상**: 같은 피부·머리를 유지한 채 캡과 유니폼을 정장으로 바꿔요. 정식 시상식 MVP/반기 MVP, 세 모드 수상 팝업, 관리자 미리보기에 연결했어요.
- **최종 자세**: 임의의 긴 팔을 붙인 첫 시안은 비율 문제로 폐기했어요. 팔을 자르는 clip-path와 덧붙인 팔 SVG를 모두 제거했어요. 구매 시트의 정면 `gift` 30~35번 프레임(행 10)을 사용해 짧은 원본 팔·손으로 트로피를 몸 앞에서 받쳐 들어요. 얼굴·팔·몸 비율을 유지해요. 첨부처럼 머리 위로 드는 자세는 현재 구현했다고 주장하지 않아요. 그 포즈를 확장할 때는 전용 프레임 작화를 먼저 검토해야 해요.
- **표현**: 정수 배율·pixelated 렌더, 화면 밖/탭 숨김 시 애니메이션 정지. 동작 줄이기·JS OFF에서는 정적 외형. 이미지 누락은 인물 아이콘으로 대체해요.

핵심 파일은 `community/rookie_avatar.py`, `rookie_avatar_tags.py`, `static/css/rookie-avatar.css`, `static/js/rookie-avatar.js`, `_rookie_avatar.html`, `_rookie_avatar_picker.html`이에요. 게임 엔진의 생성 수치·성장·경기 난수는 수정하지 않았어요.

## 검증 근거

- `manage.py check` 통과.
- `community.test_rookie_avatar`, `community.test_rookie_flow`, `community.test_rookie_full_design`, `community.test_rookie_extreme`: 전체 커리어 HTTP 요청 흐름 포함 **36개 통과** (`scratchpad/rookie-avatar/tests.log`).
- 최종 추가 검사는 `community.test_rookie_avatar`(9개)·`community.test_rookie_full_design`(9개): **18개 통과**, 외형을 고른 선수의 은퇴까지 저장 유지 포함 (`avatar-tests-final.log`). 위 검사와 일부 중복돼요.
- `browser_flow.js`: PC 1366 / 실제 모바일 UA·쿠키 390·320 × 세 모드. 실제 생성 POST, 새로고침 후 외형 유지, 수상 때 같은 피부·머리/정장, JS 오류·페이지 가로 넘침 없음.
- 세 모드·세 폭에서 최종 수상 자세의 추가 팔 0개, clip-path 없음, 얼굴/수상 제목 겹침 없음 재검증. `award-{full,lite,extreme}-{1366,390,320}.png`.
- JS OFF로 외형 선택·실제 입단·저장·정적 아바타 확인. 동작 줄이기/JS OFF × 세 폭 × 세 모드 및 시상식에서 정적 아바타와 넘침 없음 확인. 키보드 방향키 선택·Enter 미리보기, 이미지 요청 차단 시 대체 표시 확인.
- `verify_assets.py`: 사용 PNG 35개가 구매 ZIP 원본과 바이트 단위로 동일. 모두 896×640 RGBA·투명 배경, 합계 1,343,872바이트. 원본 ZIP 및 설치 EXE를 변경·실행하지 않았어요.

실제 시상식 수상자는 기존 공개 규칙으로 조회한 선수만 표시해요. 로컬 `/__avatar/`는 별도 QA 실행 스크립트 안에만 있으며 실제 URL 설정에는 넣지 않았어요. QA 수상 팝업·명단은 미리보기이며 진짜 수상 기록을 추가하지 않아요.

## 재현·배포 준비

```powershell
py -3.10 -X utf8 manage.py build_rookie_avatar_assets --source '<구매 폴더>/Character Generator 2.0 Linux Build.zip'
py -3.10 -X utf8 scratchpad/rookie-avatar/serve.py
```

로컬 QA 서버는 `127.0.0.1:8024`와 비어 있는 별도 `qa.sqlite3`만 사용해요. 기본 `db.sqlite3`에 테스트 데이터를 만들지 않았어요. 원본 조각은 Git 제외 `media/rookie-avatar/v1/`에 35개만 설치하고, 재생성 manifest·크레딧을 함께 두었어요. 배포 때 이 미디어 묶음도 별도로 필요해요. 원본 ZIP·검토용 전체 조각·QA DB는 배포하거나 커밋하지 않아요. footer에 LimeZu 링크 크레딧을 추가했어요.

현재는 로컬 구현·검증까지예요. 운영 배포·push·마이그레이션은 하지 않았고, 외형용 DB 마이그레이션도 필요하지 않아요.

다음 확장은 타격·투구 전용 프레임, 자연스러운 머리 위 트로피 포즈, 구단 유니폼·등번호, 나이에 따른 어린이/성인 시트예요. 첨부 수준의 별도 SD 비율은 이번 선택과 다른 작화 작업으로 다뤄요. 현재 선택 가능한 아바타와 연결된 수상 동작은 로컬에서 사용할 수 있어요.

메모리 인계용 결정: 구매 원본을 다시 그리지 않고 레이어 합성으로 활용, 외형 JSON v1과 경기 계산 분리, 구매 PNG는 미디어로만 관리, 수상 자세는 원본 팔 비율 유지. 외부 메모리는 읽기만 했어요.
