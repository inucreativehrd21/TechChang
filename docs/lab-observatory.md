# 연구실 재작성 보완과 실시간 현황

2026-11-18 구현 기록이에요. 운영 배포·실제 AI 원고 품질 평가 완료를 뜻하지 않아요.

## 관리자 재작성

일반 칼럼과 관리자 요청이 있는 연재에 적용해요. 최초 요청별 편집·검수 이후, 최종 심사에서 미이행·점수 하락·새 결함을 발견하면 **같은 요청 안에서 최대 두 번 추가 보완**해요.

- 직전 후보를 기준으로 편집해요. 원래 요구 ID·문구·완료 기준을 바꾸지 못해요.
- 기존 심사, 요청별 검수 결과, 새 팩트체크·편집 지적을 보완자에게 전달해요. 다음 요청에도 지난 실패 사유를 전달해요.
- 보완 뒤 사실 검증·후처리·심사·요청별 검수를 다시 거쳐요. 본문이 그대로인 후보의 점수만 다시 받지 않아요.
- 재작성 호출 상한은 24회에서 40회로 늘려요. 40분 실행 예산, 구독 입력 상한, 실행기의 45분 제한은 유지해요. 보완 착수에는 10회·240초 이상 여유가 필요해요.
- 구독 한도·호출 실패는 추가 보완으로 반복 호출하지 않아요. 점수 하락이나 미반영이 남으면 기존 원고·점수·도판을 보존해요. 운영자 승인 절차도 유지해요.
- `--review-only`는 사람이 교열한 원고를 그대로 심사해요. 추가 집필 보완을 적용하지 않아요.

실제 모델 응답의 품질과 점수 일관성은 사람 평가가 필요해요. 테스트는 모의 AI 응답으로 보완·재검수·원고 보존 계약을 검증해요.

## 별도 실시간 화면

주소는 `/lab/admin/observatory/`예요. 기존 연구실·관리 화면 템플릿과 배치는 변경하지 않았어요.

- 작업 목록 → 기획·집필 / 검증·도판 / 편집·판정 → 에이전트별 호출·산출물 계층으로 표시해요.
- 실행 중 작업을 우선 선택해요. 현재 호출을 먼저 보여주고 이전 기록은 펼쳐서 확인해요.
- 3초마다 상태를 조회해요. 갱신 멈춤·재개, 실패 시 재시도 간격 증가, 숨긴 탭의 폴링 중지, 인증 만료 시 중지를 지원해요.
- 실제 호출 시작·완료는 `office.activity`가 기록하고, 단계 산출물은 `StageRun`에서 읽어요. 완료 응답을 보여주며 토큰 단위 스트리밍이나 내부 추론은 표시하지 않아요.
- 원고가 없는 대기 작업도 표시해요. 종료된 작업·만료된 실행 권한·이전 실행 번호의 호출을 계속 실행 중으로 표시하지 않아요.
- 페이지·상태 JSON·상세 JSON 모두 기존 연구실 운영자 권한과 OTP 경계를 적용하며 캐시하지 않아요. IP 차단은 유지하고, OTP가 유효한 운영자의 두 조회 주소에만 일반 요청 집계를 제외해요. 다른 경로·POST·비인증 요청에는 적용하지 않아요.

## 관측 데이터

`logs/private-lab/activity/<run UUID>.json`에 실행별 관측 요약을, `<run UUID>/<call ID>.txt`에 완료 응답을 원자적으로 저장해요. 프롬프트나 내부 추론은 저장하지 않아요. 동시에 실행하는 검토자는 같은 실행의 잠금으로 상태를 병합해요. 관측 저장 실패가 실제 집필·검증을 중단하지 않아요.

화면은 최근 7일 관측 중 최신 30개 실행과 최근 단계 기록, 활성·최근 작업을 읽어요. 실행별 호출은 최근 120개, 전체 화면은 최대 40개 작업을 표시해요. 호출 응답은 16,000자, 단계 상세는 24,000자까지 표시하고 생략 여부를 알려줘요. 긴 내용은 클릭할 때 별도 조회해 정기 폴링 크기를 줄여요. 과거 작업은 저장된 단계만 볼 수 있어요. 이 변경은 원본 `StageRun`을 삭제하거나 관측 파일 정리 주기를 추가하지 않아요.

DB 모델·마이그레이션은 추가하지 않아요. 새 설정 `LAB_ACTIVITY_ROOT`는 테스트나 별도 비공개 저장 위치가 필요할 때만 사용해요.

## 확인 방법

`office.test_observatory`, `office.test_revision_requests`, `office.test_series_pipeline`에서 동시 관측, 대기·중단·재시작, 권한·OTP·요청 제한, 일반·연재 추가 보완과 원고 보존을 확인해요. 기존 재작성·승인·중복 요청 회귀 테스트도 함께 실행해요. PC·모바일 화면 검증에는 격리된 테스트 DB와 모의 작업을 사용해요.
