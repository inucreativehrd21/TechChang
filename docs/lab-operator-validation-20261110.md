판매·고객별 SaaS 격리·납기 목표를 제외한 발행 안전성, 복구, 품질·사용량, 운영, 감사가 대상이에요. 현행 정책과 적용 순서는 [운영 문서](lab-operator-hardening.md)에 있어요.

## 로컬에서 확인한 것

`py -3.10 manage.py test office common --noinput --verbosity 1`에서 **672개 실행, 실패 0, 환경 조건으로 1개 제외**였어요. 최종 기록은 `logs/lab-operator-hardening-final-v4.log`예요. MySQL의 실제 행 잠금 테스트는 SQLite 환경에서 실행하지 않았어요. MySQL 8 CI 작업은 추가했지만 원격 CI 실행 결과는 아직 없어요.

다음은 회귀 테스트로 확인했어요.

- 사실 검증 실패·검증/심사 버전 불일치의 공개 차단, 형식만 허용하는 명시적 예외 승인, 변경 시 승인 무효화.
- 화면에 표시한 원고·근거의 지문을 승인 요청에 전달. 화면을 연 뒤 근거가 바뀌거나 지문이 빠진 요청의 승인 거절.
- 만료 실행의 저장 거절, 실행 번호가 바뀐 뒤 이전 결과의 저장 거절, 만료 작업 종료·격리, PID 재사용 보호.
- 시작 후 오류와 종료 미확인의 격리. 실제 로컬 자식 프로세스의 시작 신원 확인과 종료 확인. Linux 좀비 상태의 분류는 모의 입력으로 확인했어요.
- 비운영자 관리자/메일 링크 접근 차단, office 권한을 모두 받은 일반 staff의 Django 기본 관리자 접근 차단, 원본 CLI 로그의 OTP 경계.
- 모델 CLI 환경의 DB·메일·API 비밀값 제거, 파일/설정 주입 인자 차단, 공개 상태의 내부 회의·미발행 원고 캐시 문구 제거.
- 감사 사건의 응용 계층 수정·삭제 차단, 해시 체인 검증, 직렬화한 감사 자료의 별도 파일 SQLite 복원·재검증.
- 부분 실증 재개의 블라인드 번호·사람 평가 보존, 잘못된 A/B 쌍·비정상 평가 값 거절, 미측정 사용량 구분, 승인 표본의 과거 실패 시도 비용 포함, 단계 도중 실패한 호출의 사용량 보존과 중복 집계 방지.

Django `check`, `makemigrations --check --dry-run`, `git diff --check`도 통과했어요. 마이그레이션은 독립 테스트 DB에서만 적용했어요.

## 접근·파일·로그 경계

운영 사이트에는 읽기 전용 HTTP 요청으로 HEAD/GET 응답 헤더를 확인했어요. 응답 본문은 읽거나 출력하지 않았어요(`logs/lab-isolation-production-headers.log`).

| 경로 | HEAD / GET |
|---|---|
| `/.env`, `/.git/config` | 403 / 403 |
| `/logs/office_jobs.log`, `/logs/lab-runs/`, `/logs/private-lab/` | 404 / 404 |
| `/backups/`, `/scratchpad/` | 404 / 404 |
| `/lab/admin/activity.json` | 로그인 302 / 302 |

현재 운영 경계의 관측 결과예요. 이번 새 코드를 배포한 뒤의 검증이나 서버 파일 ACL 검증을 의미하지 않아요. 동일 관리자 OS 계정 내부를 고객별 보안 경계로 취급하지 않아요.

## 품질·경제성 실증

고정 블라인드 번호가 있는 12편 목록은 `logs/private-lab/operator-pilot-release-20261110/manifest.json`에 준비했어요. 완성 원고의 독립적인 관리자 검수 없이 B 전환이나 품질 향상을 확정하지 않아요. 토큰은 제공자 기록의 사용량 지표이며 금액·구독 한도 차감량과 같지 않아요.

별도 `operator-pilot-20261110` 폴더에서 A 한 편의 실제 구독 smoke 실행을 완료했어요. 모델 호출은 22회, 기록된 모델 시간 합은 1,125초(18분 45초), 편집 심사는 70점 → 80점, 최종 판정은 `minor`였어요. 두 심사 모두 필수 수정 관문은 통과하지 않았어요. `final` 단계와 제목을 포함한 원고·단계 JSON·블라인드 파일을 보존했어요. dry-run/no-publish 실행이므로 운영 원고를 만들거나 실제 공개를 시도한 시험은 아니에요.

22개 호출 모두 제공자 사용량이 기록됐어요. Claude 신규 입력 84, 캐시 생성 입력 235,897, 캐시 읽기 입력 223,976, 출력 104,412토큰으로 각각 구분해요. 신규 입력만 보고 저비용이라고 해석하지 않아요. 이 값은 구독 차감량·금액이 아니에요. 구독 경로만 사용했으며 유료 API로 전환한 기록은 없어요.

실행 도중 후속 승인·복구·사용량 기록 코드가 바뀌었으므로 이 자료는 실행 당시 소스 지문의 연동 점검 기록으로 보존하며 최종 소스의 A/B 비교 표본에 합치지 않아요. 사람 평가 항목은 비어 있으며 모델 판정을 사람 승인으로 대체하지 않았어요. 실행 프로세스와 로컬 라이브 상태는 종료됐어요.
