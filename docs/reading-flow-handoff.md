# 홈페이지와 읽기 흐름 개선 인계

2026-11-15 작업이에요. CTO 검토의 실행 순서에 따라 기능을 수정했으며, 측정 기능은 사용자 요청에 따라 후속 논의로 남겼어요. 이 문서는 로컬 검증 시점의 인계 기록이며, 운영 반영 여부는 해당 릴리스의 배포 결과를 확인해 주세요.

## 적용한 흐름

- 가입: 글·게임·검색에서 로그인 또는 가입을 거쳐 원래 주소로 돌아와요. 쿼리와 댓글 위치 앵커를 유지해요. 가입 검증 실패 시에도 목적지를 유지하고, 외부 주소·HTTPS에서 HTTP로의 전환·인증 화면을 향한 복귀는 거부해요.
- 이메일 가입: 서버는 8자리 코드를 발급하는데 가입 화면이 4자리까지만 받던 기존 오류를 수정했어요. `EmailVerification.CODE_LENGTH`를 화면과 폼이 공유해요. 이메일은 발송·검증 경로와 동일하게 소문자로 정규화하고 중복 여부는 대소문자와 관계없이 확인해요.
- 탐색: `/explore/`에서 칼럼·연재·커뮤니티 글을 함께 검색하고 주제와 유형으로 거를 수 있어요. 기존 `/?kw=...`도 200 응답의 동일한 탐색 화면을 제공해요. 검색 조건과 페이지 번호를 URL에 유지해요.
- 공개 범위: 검색은 열람 가능한 글만 대상으로 하고 문의글·삭제글과 삭제된 댓글은 검색 결과를 만들지 않아요. 비회원의 회원 전용 본문 검색도 차단해요.
- 홈: 검색과 추천 칼럼을 먼저 보여줘요. 공개 칼럼의 운영자 픽을 우선하고 최신 글로 채우며, 연재는 첫 회차만 첫 추천 후보로 사용해요. 주제·시리즈·칼럼 지도 진입을 제공하고 연구실과 게임은 아래에 배치했어요. 인기 칸은 최근 30일에 발행한 칼럼 중 조회순이에요. 최근 30일의 조회 증가량을 측정한 순위는 아니에요.
- 모바일: 하단 메뉴는 홈·탐색·커뮤니티·게임·내 활동이에요. 글쓰기는 커뮤니티에 두고, 구성원·랭킹·방명록은 내 활동에서 접근할 수 있어요. 화면 확대도 허용해요.
- 상세 복귀: 목록에서 글을 열 때 원래 검색 조건·페이지·앵커를 전달해요. 복귀 주소는 같은 사이트의 알려진 목록 화면만 허용해요. 별도 진입 정보가 없는 연재 회차는 해당 시리즈 목차로 돌아가요.

## 읽기 도구의 보관 범위

- 공개 연구팀 칼럼과 연재에만 글 저장·읽던 위치·최근 읽기 기능을 제공해요.
- 저장한 글은 최대 100편, 최근 글은 24편까지 이 브라우저의 `localStorage`에 보관해요. 계정 및 다른 기기와 동기화하지 않아요.
- 관심 주제는 HRD·데이터분석·프로그래밍 중 선택해 보관하고 해당 주제로 바로 탐색할 수 있어요.
- 최근 읽던 글은 홈에서 이어 읽을 수 있고, 마지막 부분까지 이동한 연재는 발행된 다음 회차로 연결해요. 위치는 학습 성취나 실제 완독을 판정하는 지표가 아니에요.
- 목록의 스크롤 복원에는 같은 탭의 `sessionStorage`를 사용해요.
- 본문 위로 이동해 목록이나 메뉴를 눌러도 마지막 읽던 위치를 초기화하지 않아요.
- 저장 목록과 최근 목록은 내 활동에서 확인 후 비울 수 있어요. 브라우저 저장소가 차단되면 보관 실패 안내를 표시해요.
- 저장 데이터는 허용된 숫자형 글 경로만 사용하고 제목은 `textContent`로 표시해요. 저장소 값이 손상돼도 콘텐츠 탐색은 동작해요.
- 이 기능에서 서버로 읽기 기록을 보내거나 분석 서비스를 추가하지 않았어요. 기존 방문자 집계 방식도 변경하지 않았어요.

## 주요 코드

- `common/navigation.py`, `common/templatetags/navigation_tags.py`: 가입 및 메뉴의 안전한 복귀 주소
- `common/views.py`, `common/forms.py`: 가입 복귀와 인증 코드 입력·이메일 정규화
- `community/views/explore_views.py`: 통합 탐색과 목록 복귀 주소
- `community/views/base_views.py`: 홈 추천과 상세 읽기 도구 노출 조건
- `templates/community/_home_content.html`: PC·모바일 공통 홈 본문
- `templates/community/explore.html`, `reading_list.html`, `_reading_tools.html`: 탐색·읽기 목록·저장 도구
- `static/css/reading-flow.css`, `static/js/reading-flow.js`: 화면 구성과 브라우저 읽기 상태
- `community/test_reading_flow.py`: 검색·권한·가입 복귀·화면 분기 회귀 검사

## 검증 결과

- 최종 관련 Django 테스트 131개 통과: 읽기 흐름, 홈 연구실, 칼럼 반응, 사이트 정보·운영, SEO, 비공개 글, 운영자 픽, 칼럼 지도, 가입 동의, 소셜 로그인, 크롤러, HTTP 메서드, 메일 실패 처리
- `manage.py check --settings=config.settings.local`: 문제 없음
- `node --check static/js/reading-flow.js`: 통과
- 기존 CRLF 파일 형식을 유지하고 `git -c core.whitespace=cr-at-eol diff --check` 통과
- 독립 메모리 DB와 콘솔 메일 서버에서 이메일 인증 → 가입 → 원래 글·댓글 앵커 복귀를 브라우저로 확인
- 검색에서 연재 회차 발견, 검색 결과의 글 진입과 복귀, 유형·페이지·스크롤 복원 확인
- 저장 목록·관심 주제 새로고침 유지, 읽던 위치 복원, 다음 발행 회차로 연결 확인
- 저장 데이터의 HTML 문자열 및 외부 실행 주소 처리, 손상된 JSON, 저장소 쓰기 차단 확인
- JavaScript를 끈 상태에서도 추천 링크와 검색 결과 열람 확인
- PC 1440px·1024px, 모바일 User-Agent 및 버전 쿠키를 적용한 320px·390px·768px에서 확인. 점검한 홈·탐색·내 활동·가입 화면의 가로 넘침 없음

OAuth 공급자에서 실제 인증을 완료하거나 운영 메일을 발송하지 않았어요. 소셜 로그인은 기존 회귀 테스트로 확인했고 이메일 화면 흐름은 외부 발송이 없는 검증 서버에서 확인했어요. 테스트 서버는 작업 후 종료해 메모리 DB의 임시 데이터를 폐기해요.

## 메모리에 남길 결정

측정과 기능 보관을 분리했어요. 읽기 상태·관심 주제는 브라우저 보관, 콘텐츠 검색은 하나의 공개 탐색 화면, 홈 본문은 PC·모바일 공통 구성으로 운영한다는 결정이 후속 작업에서 중요해요. 저장소 밖 Claude 메모리는 수정하지 않았어요.

측정 지표·외부 분석 도구·이벤트 수집·방문자 집계 개선은 별도 논의 대상이에요.

## 운영 반영 전 추가 검증

전체 CI 1,412개 검사에서 홈 개편 중 프리미엄 배지 누락을 발견해 운영 반영 전에 보완했어요. 공통 카드의 프리미엄 표시를 복구하고 통합 탐색에도 같은 심사 기준을 적용했어요. 테스트는 옛 배치의 고정 카드 수 대신 각 카드가 프리미엄 자격에 맞게 표시되는지 확인하도록 바꿨어요. 보완 후 관련 테스트 38개를 통과했고, 운영 반영 전 전체 CI를 다시 확인해요.
