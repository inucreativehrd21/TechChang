# 회의 주제·의견 일괄 검토와 저장

> 이후 운영자 요청으로 운영에 적용했어요. 현재 배포·검증 결과는 [운영 반영 기록](lab-production-release-20261112.md)을 참고해요. 아래 미배포 표기는 최초 로컬 검증 시점의 기록이에요.

운영자가 지적한 “여러 안건을 선택하고 하나를 저장하면 다른 선택이 풀리는 문제”를 수정했어요. 운영 적용 전 로컬에서 구현·검증한 변경이며 운영 서버 배포는 하지 않았어요.

## 원인과 화면 변경

기존에는 안건마다 개별 폼과 결정 버튼이 있었어요. 여러 안건에서 고른 내용 중 한 폼만 POST되고 화면 전체가 다시 열리면서, 다른 폼의 미저장 선택·메모가 사라졌어요. 각 폼의 라디오 필드 이름도 모두 `key`였으므로, 폼을 합칠 때는 안건별로 이름을 분리해야 했어요.

회의 전체를 한 폼으로 묶고 `choice_<안건 ID>`·`note_<안건 ID>`로 선택과 의견을 구분했어요. 안건별 후보는 하나씩 고르되, 여러 안건을 모두 검토한 뒤 **선택·의견 한 번에 저장**을 눌러요. 일부 안건만 결정하거나, 미결정 안건의 의견만 먼저 적어 저장할 수도 있어요. 주제 선택은 원고의 검수·게시 승인을 대신하지 않아요.

화면에는 분야·심화/실용 유형, 후보 설명·제안자·검색 수요 참고값, 저장됨/미저장/미결정 상태를 보여줘요. 선택한 주제·의견을 모은 요약과 고정 저장 버튼, 선택 개수·미저장 변경 개수도 함께 보여줘요. 추천을 자동 선택하거나 운영자 판단을 대신하지 않아요.

아직 제작에 쓰이지 않은 저장된 결정은 다시 고를 수 있어요. 원고가 연결됐거나 이미 반영된 안건, 정비 작업으로 넘어간 안건은 변경을 잠가 기존 제작의 근거가 바뀌지 않게 해요. 마지막 수정 의견은 미결정 안건에서도 보존돼요.

## 저장 동작

- 회의·안건을 잠그고 모든 변경을 먼저 검증한 뒤 한 트랜잭션으로 저장해요. 잘못된 선택·300자 초과 의견·동시 편집 충돌·서명 오류가 있으면 전체 변경을 저장하지 않아요.
- 오류 화면에서 다른 안건의 선택과 의견을 그대로 표시해요. 충돌한 안건에는 현재 저장된 주제·의견을 함께 보여줘 비교할 수 있어요.
- 검토 화면의 초기 선택·의견과 버전 지문을 서명해 전달해요. 다른 화면이 바꾼, 이번 화면에서 손대지 않은 안건은 덮어쓰지 않아요. 이번 화면에서 변경한 안건이 충돌하면 다시 확인하도록 해요.
- 같은 요청을 반복해도 결정 로그·정비 작업·후속 요약을 중복 생성하지 않아요. 안건 전체가 결정됐을 때 기존 공개용 회의 요약을 한 번 예약해요.
- 선택·의견 변경을 비공개 감사 기록에 남겨요. 선택이 바뀌면 기존 공개 소개·요약을 비우고 새 결정 기준으로 다시 만들어요. 운영자 의견을 공개 안건의 원문 상세에 섞지 않아요.
- 개별 저장의 이전 URL도 같은 검증·잠금 규칙을 사용해 우회 경로로 남기지 않아요.
- 미저장 변경이 있을 때 페이지를 떠나면 브라우저 경고를 사용하고, 작업 로그 폴링이 자동으로 화면을 새로고침하지 않게 해요. 운영자 의견을 브라우저 저장소에 따로 남기지 않아요.

칼럼 의견은 `Decision.note`에 저장할 뿐 아니라 기획서·설계도·집필 프롬프트에도 함께 전달해요. 이를 검증된 사실로 간주하지는 않아요. 개발·운영 안건 의견은 생성되는 정비 작업 본문에 함께 넣어요. 새 AI 호출 단계나 유료 API 경로는 추가하지 않았어요.

## 검증

집중 검사 36개와 `office`·`common`·공개 지도·홈의 회귀 검사 **763개에서 실패 0, MySQL 전용 3개 제외**였어요. 이후 공개 요약 무효화 보완과 그 회귀 검사를 포함한 최종 집중 검사 **50개도 모두 통과**했어요. 검사 묶음은 겹치므로 합산하지 않아요.

검사 항목은 여러 주제·의견 일괄 저장, 부분 결정·의견만 저장, 새로고침 후 보존, 잘못된 선택 시 전체 롤백, 긴 의견 보존, 동시 편집 충돌, 손대지 않은 안건의 최신 결정 보존, 기존 결정 재검토, 제작된 결정 잠금, 선택지 정의 변경, 토큰·안건 ID 변조, DB 오류 롤백, 비운영자·CSRF 차단, 의견의 실제 집필 프롬프트 전달이에요.

별도의 임시 SQLite DB와 실제 Django 뷰를 사용한 로컬 서버에서 PC 1280px·모바일 390px을 조작했어요. 두 주제를 고르고 의견을 적은 뒤 한 번 POST하고, 새로고침해도 두 선택과 의견·미결정 안건의 메모가 유지되는 것을 확인했어요. 모바일은 User-Agent와 `force_version=mobile`, `header.m-header`로 실제 분기를 대조했고, 가로 넘침과 의견 입력란·저장 바 겹침이 없었어요. 잘못된 선택으로 409 응답을 받았을 때도 다른 선택과 입력 의견이 남는 것을 브라우저에서 확인했어요.

화면 자료는 `scratchpad/lab-meeting-decisions/`의 `desktop.png`, `mobile.png`, `mobile-viewport.png`, `error-preserved.png`예요. 긴 폼 전체 캡처에는 촬영 시점의 고정 헤더·저장 바가 포함되며, 실제 입력란 가림 여부는 뷰포트 캡처와 좌표로 따로 확인했어요. UI fixture의 후속 작업 예약은 가짜로 처리해 실제 모델·메일을 실행하지 않았어요. 임시 서버는 종료했어요. `tmp/meeting-review-preview-a6bpic4h`의 테스트 DB 폴더는 정리 명령이 자동 승인 검토에서 “blocked by policy”로 거절돼 남겨뒀으며 삭제를 우회·재시도하지 않았어요. 기존 개발 DB나 운영 DB에는 적용하지 않았어요.

검사 로그는 `logs/lab-meeting-decisions-focused-20261112.log`, `logs/lab-meeting-decisions-regression-20261112.log`, `logs/lab-meeting-decisions-final-20261112.log`예요. Django check·마이그레이션 상태 검사·diff 검사도 통과했어요. 이번 변경은 기존 필드를 사용하므로 새 마이그레이션이 없어요. 기존 두 유형 편성에 필요한 미배포 마이그레이션과는 별개예요.

운영 코드·DB·회의 결정은 변경하지 않았어요. 메모리에 남길 비자명한 결정은 “회의별 일괄 저장과 부분 결정 허용”, “제작 전 결정만 재검토”, “운영자 의견의 실제 집필 전달”, “미저장 입력이 있으면 폴링 새로고침 금지”예요. 저장소 밖 메모리는 수정하지 않았어요.
