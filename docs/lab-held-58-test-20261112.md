# 운영 보류 원고 #58 사본으로 관리자 수정 실증

> 아래는 최초 사본 시험의 실패와 원본 보존 기록이에요. 이후 사용자 요청으로 원고를 직접 교열·재검수해서 88점으로 게시했고, 발견한 후처리 결함도 로컬에서 수정했어요. 현재 발행 상태와 후속 검증은 [후속 보고서](lab-publication-postprocessing-20261112.md)에 기록했어요. 아래의 “운영 원고는 보류 상태 그대로” 등은 최초 시험 직후 시점의 설명이에요.

사용자가 운영 서버의 보류 원고로 시험하도록 요청했어요. 운영 원고를 읽어 비공개 사본을 만들고, 새 로컬 코드와 독립 SQLite 테스트 DB에서 A 프로필의 `office_revise --no-publish`를 실행했어요. 운영 코드를 배포하거나 원고·DB·서비스를 변경한 시험은 아니에요.

## 입력과 원본 보존

- 운영 원고: #58 「남은 두 달 카드 배분, 내 계산표로 정하기」, data 칼럼, 보류, 66점, 본문 7,915자, 차트 이미지 1개
- 저장된 관리자 지시: “편집장 필수 수정과 팩트체크 지적을 모두 반영해 고쳐 주세요”
- 기존 편집장 필수 수정 4개: 차트 지수 표기·단위/설명, 맺음말 조건 분기, 리드와 실제 결과물 일치, 법령 링크
- 실행 소스: `279f6d8218f3d7df1aa9e06c3fa8546411d68822ac6cb2ace697086555404e20`
- 운영 원고의 선택 필드 전체 지문: `1faec49726d12d55ba3324e70a3b36fddeb0c29114fe977af0c3491175999803`

운영 원고와 차트는 시험 전후 지문이 모두 같았어요. 운영 원고는 66점 보류 상태 그대로예요. 원고·검증 보고서·원본 차트 사본과 결과는 `logs/private-lab/live-hold-58-test-20261111/` 아래에 비공개로 보존했어요. 입력을 자정 전에 가져와 폴더 이름은 11월 11일이며 실제 시험은 11월 12일에 끝났어요. 서버에서 읽기용으로 만든 `/tmp` 스크립트와 스냅샷 파일은 확인 후 제거했어요.

## 실제 결과

**수정 완료 통과가 아니라 미채택·원본 유지**였어요. 모델 심사 점수는 **66→67점**, 후보 판정은 major였어요. 실제 구독 모델 호출 7회, 기록된 모델 시간 합계 493.6초, 경과 시간 498.0초였어요. 유료 API와 B 전환은 사용하지 않았어요.

| 세부 요청 | 최종 요청 검수 |
|---|---|
| 차트 값·단위를 조 원으로 통일하고 정상 렌더링 | 미완료 — 이미지 마크다운 손상, 새 이미지 연결 없음 |
| 캡션을 B15→B17 계산 구조와 연결 | 반영 확인 |
| 맺음말의 세 가지 조건 분기 | 반영 확인 |
| 시사점 첫 항목을 같은 분기 순서로 정리 | 반영 확인 |
| 리드를 실제 기호 표의 내용과 맞추기 | 반영 확인 |
| 법령 링크를 실제 조문이 열리는 주소로 바꾸기 | 확인 불가 — 주소 교체만으로 조문 내용 접근을 입증하지 못함 |
| KOSIS 최신 귀속 판 공표 여부 확인 | 확인 불가 — 모델 도구에서 SSO 리다이렉트로 원표를 확인하지 못함 |

총 7개 중 4개가 반영 확인, 3개가 미완료·확인 불가였어요. 기존 핵심 편집 지적 4개로 묶으면 조건 분기와 리드 2개는 해결됐고 차트와 법령 링크는 해결되지 않았어요. 기존에 통과로 저장된 일부 통계도 이번 재검증에서는 직접 근거를 확인하지 못해 unverified_data가 생겼어요. 이 문서는 세법 내용이나 통계의 진위를 독립적으로 확정한 보고서가 아니며, 모델 검수와 접근 실패 기록을 구분해 적었어요.

새 요청 검수가 차트 손상과 요청 미완료를 탐지했고, 기존 통과 사실 검증의 실패도 채택을 막았어요. 테스트 DB에서도 기존 원고·점수·기존 차트를 유지했으며 후보는 별도로 남겼어요. 운영 원고 교체·발행·새 사람 승인은 하지 않았어요.

## 확인한 후처리 결함

기록된 작성 후보와 실제 첫 팩트체크 보고서를 사용해 `P.lock_numbers`를 모델 호출 없이 재생했어요. 작성 후보의 이미지 마크다운은 완전했으나, 수치 잠금 이후에는 `![그림 1.`만 남았어요. 새로 들어온 조 원 단위의 반올림 값이 든 뒷부분과 이미지 URL이 함께 삭제됐어요. `E.drop_sentences`가 이미지 대체 텍스트의 `그림 1.` 뒤를 일반 문장처럼 나눠 처리한 결과예요.

그 뒤 도판 단계는 그림 캡션 등이 남은 본문을 기존 그림이 있는 것으로 해석해 새 렌더링을 생략했어요. 따라서 단순히 작성자가 요청을 무시한 문제만은 아니고, 코드 후처리도 완료된 편집을 깨뜨릴 수 있다는 증거예요. 요청 검수 방어는 동작했지만 이 후처리 결함 자체는 이번 시험에서 수정하지 않았어요.

다음 우선 수정 대상은 수치 잠금에서 이미지·링크 마크다운을 안전하게 다루는 것과, 손상된 도판 블록의 탐지 및 재생성이에요. 확인하지 못한 법령·통계를 통과시키거나 검증 기준을 낮추는 방식으로 해결하면 안 돼요.

## 이번 시험 준비 중 보강한 것과 검증

포괄적인 “기존 지적 모두 반영” 요청에서 원문 한 줄만으로는 수행 범위를 검수하기 어려운 점을 확인했어요. 기존 필수 수정·팩트체크 지적·메모를 작성자와 독립 검수자에게 함께 넘기고, 모든 참조 지적 ID가 수정 항목에 연결되는지 검사하도록 보강한 뒤 시험했어요. 미채택 후보의 심사 호출 사용량도 후보 판정 단계에서 빠짐없이 기록하도록 했어요.

관련 검사 65개와 추가 참조·사용량 검사 포함 18개가 통과했고, 최종 소스의 office/common 회귀 검사는 **708개에서 실패 0, MySQL 환경 전용 3개 제외**였어요. 숫자는 겹치는 검사 묶음이므로 합산하지 않아요. Django check와 diff 검사도 통과했어요. 이 자동 검사 통과를 실제 편집 성공으로 해석하지 않아요.

계측상 제약도 있어요. `metrics.json`의 심사 횟수는 정식 `review` 단계만 세어 미채택 후보의 심사를 0회로 표시해요. 실제 67점 심사는 `stages.json`의 `revision_decision.output.review`에 있고 7회 호출 사용량은 모두 기록됐어요. 이 사례의 품질·심사 판정은 그 실제 보고서를 근거로 했어요. 후보 심사의 집계 표현도 후속 보완 대상이에요.
