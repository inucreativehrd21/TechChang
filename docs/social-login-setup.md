# 기존 계정 연결과 Google 로그인

기존 회원은 아이디·비밀번호로 로그인한 뒤 **프로필 → 로그인 계정 연결**에서 카카오나
Google을 연결해요. 다음 로그인부터 연결한 소셜 계정을 사용해도 기존 포인트·선수·글이
같은 사용자에 남아요. 이메일이 같다는 이유로 계정을 자동으로 합치지 않아요.
이미 다른 회원에게 연결된 소셜 계정은 거절하고, 소셜 전용 계정의 마지막 로그인 수단은
해제할 수 없어요. 비밀번호가 있는 계정의 해제는 현재 비밀번호를 확인해요.

일반 로그인 성공 후 아직 소셜 계정이 연결되지 않은 회원에게 로그인당 한 번 안내 팝업을
보여 줘요. **계정 연결하기 → Google / 카카오 계정 연결하기 → 공급자 인증** 순서예요.
‘나중에 할게요’나 Escape로 닫을 수 있고, 연결 화면에 직접 들어가면 팝업을 생략해요.
이미 소셜 계정이 연결됐거나 소셜로 로그인했다면 팝업을 띄우지 않아요.

## 회원 데이터의 공통 기준

- 모든 로그인 방법이 같은 `auth.User.id`를 사용해요. 이메일은 `User.email`, 닉네임·사진·포인트·인증·약관 동의는 `Profile`에 보관해요.
- Google과 카카오는 같은 `SocialIdentity(user, provider, subject)` 형식이에요. 공급자별 식별자는 하나의 회원에게만, 회원당 공급자 하나씩 연결돼요.
- 명시적 연결은 회원 번호·프로필·기존 비밀번호를 바꾸지 않아요. 다른 공급자 이메일로 기존 이메일을 덮어쓰지 않아요. 공급자가 **같은 이메일**의 소유권을 확인한 경우에만 사이트 이메일 인증 상태를 갱신해요.
- 로그인 수단과 이메일 인증 여부는 별개예요. 실제 소셜 연결이 있으면 공급자 인증으로 사이트를 이용할 수 있지만, 다른 이메일을 인증 완료로 표시하지 않아요. 아이디 접두사는 인증 근거로 사용하지 않아요.
- 새 소셜 가입은 사이트 비밀번호가 없으므로 사용할 수 없는 비밀번호로 저장해요. 기존 회원의 비밀번호는 그대로 보존해요.
- 예전 카카오 전용 계정의 무작위 비밀번호도 바꾸지 않아요. 탈퇴 시에는 해당 레거시 아이디와 실제 카카오 연결이 함께 확인될 때만 기존 확인 문구 방식을 유지해요. 접두사만 같은 일반 회원은 비밀번호 확인을 거쳐요.
- `common 0016`은 누락된 Profile을 만들고, **실제 연결과 예전 카카오 행이 모두 확인되는 회원만** 빈 닉네임·더미 이메일을 보완해요. 기존 값·회원 번호·연관 기록·비밀번호·동의 기록은 유지해요. 출처가 확인되지 않은 이메일을 인증 처리하지 않아요.
- 예전 `kakao_users` 테이블은 호환용으로 남겨 두되 새 로그인에서 읽거나 쓰지 않아요. 보완한 레거시 행의 사용하지 않는 토큰은 비워요. 사용자 프로필의 기준은 항상 공통 User/Profile이에요. 이 토큰 정리는 되돌림 마이그레이션으로 복구하지 않으므로 배포 전에 DB를 백업해요.
- 이미 별도 회원 번호로 가입한 두 계정의 기록을 합치는 기능은 없어요. 기존 계정으로 먼저 로그인해 연결해야 해요.

## Google Cloud에서 한 번 설정하기

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 선택하거나 만들어요.
2. Google Auth Platform의 Branding·Audience·Data Access를 설정해요. 앱 이름은 테크창,
   홈페이지는 `https://techchang.com`, 처리방침은 `https://techchang.com/privacy/`,
   약관은 `https://techchang.com/terms/`를 등록해요. 필요한 범위는 `openid email profile`뿐이에요.
3. Clients에서 OAuth 클라이언트 ID를 만들고 유형을 **웹 애플리케이션**으로 선택해요.
   승인된 리디렉션 URI에 `https://techchang.com/common/google/callback/`을 정확히 넣어요.
   `www` 주소를 별도 서비스한다면 그 호스트의 콜백도 별도로 등록해야 해요.
4. 테스트 상태면 본인 Google 계정을 테스트 사용자에 추가해요. 일반 공개 전에는 게시 상태와
   Google이 요구하는 도메인·브랜딩 검증을 콘솔에서 확인해요.
5. 서버의 기존 `.env`에 `GOOGLE_CLIENT_ID`와 `GOOGLE_CLIENT_SECRET`을 직접 넣어요.
   값은 채팅·Git·스크린샷에 남기지 않고 파일 권한 600을 유지해요.
6. 준비된 코드와 common 0015 마이그레이션을 적용하고 웹 서비스를 한 번 재시작해요.
   두 설정이 있어야 PC·모바일 로그인 화면의 Google 버튼이 나타나요.
7. 실제 계정으로 신규 가입→약관 동의→로그아웃→재로그인, 기존 계정 연결→재로그인,
   연결 충돌·해제까지 확인해야 **운영 연결 완료**예요. 모의 테스트만으로는 완료가 아니에요.

카카오는 기존 앱과 `/common/kakao/callback/`을 유지해요. common 0015는 기존 카카오
사용자와 실제 KakaoUser 기록을 연결 식별자로 옮겨 기존 회원 기록을 유지해요.
새 로그인은 토큰을 DB에 보관하지 않고 공급자와 고유 사용자 식별자만 저장해요.
Google은 ID 토큰의 서명·발급자·대상·만료를 공식 google-auth로 검증하고 nonce와 state를
세션에서 한 번만 소비해요. 외부 주소를 로그인 완료 후 이동 위치로 허용하지 않아요.

설정·실계정 인증 전 Google은 준비 중 상태예요. 공고 중 처리방침에 Google 로그인 수집
항목도 반영하고 실제 공개 시점의 안내와 일치시켜야 해요.

- [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect)
- [카카오 로그인 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api)
