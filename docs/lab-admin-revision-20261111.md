# A 관리자 수정 요청과 집필 기준 개선

운영자 결정은 **B 기본 전환 보류, A 유지**예요. 프로필·모델·유료 API 정책은 바꾸지 않았어요. 이전 12개 실증은 이전 소스의 기록으로 보존하며 이번 변경 결과와 합치지 않아요.

2026-11-12 후속 작업에서 보류 원고 #58을 교열·심사 후 게시하고, 수치 잠금의 마크다운 손상·차트 숫자 표기·미채택 심사 집계를 보완했어요. 최신 검증 결과와 운영 반영 범위는 [후속 보고서](lab-publication-postprocessing-20261112.md)를 참고해요.

## 확인한 원인

`office_revise`는 관리자 지시와 직전 심사 지적을 함께 주고 원고 전체를 다시 쓰게 했어요. 응답이 비었거나 잘렸는지는 확인했지만, 요청별 수행 여부를 독립 검증하지 않았어요. 이후 도판 재생성·제목 변경·수치 잠금으로 수정이 되돌아가도 결과를 기존 원고에 덮어썼어요. 연재 관리자 수정도 후속 자동 보완을 거친 최종 결과의 요청 이행 확인이 없었어요.

## 변경한 동작

- 관리자 요청의 원문 인용·개별 요구·완료 기준을 최대 16개 항목으로 구조화해요. 모든 편집은 요구 ID와 원고에서 한 번만 일치하는 find/replace에 연결돼요. 불일치 편집은 부분 적용하지 않아요. 요청 밖 제목은 변경하지 않아요.
- 별도 편집 검수 호출이 원래 요청 전체, 항목 목록, 수정 전후 원고를 대조해요. 누락된 요청·미반영·요청 밖 변경·새 문제를 확인하고, 완료 근거 인용이 실제 후보에 있는지 코드로 검사해요. 작성자의 자기 보고만으로 완료 처리하지 않아요.
- 운영 보류 원고 #58을 시험하며 “편집장 필수 수정과 팩트체크 지적을 모두 반영”처럼 기존 지적을 참조하는 요청도 보강했어요. 실제 필수 수정·팩트체크 지적·메모를 작성자와 독립 검수자에게 함께 전달해요. 전체 반영 요청에서는 모든 참조 지적 ID가 수정 항목에 연결돼야 해요. 특정 부분만 수정하라는 요청에는 다른 지적을 추가 요구로 강제하지 않아요.
- 미반영 또는 형식 오류는 최대 한 번 더 편집해요. 제공자 한도·호출 오류는 이 반복에서 재시도하지 않아요. 두 번째에도 실패하면 기존 원고를 유지해요.
- 차트를 새로 그리라는 요구는 실제 렌더 뒤 검수해요. 나머지 수정은 기존 도판을 보존하고, 지운 도판을 자동 재생성하지 않아요. 관리자 수정 때 제목 실험실을 자동으로 다시 실행하지 않아요.
- 팩트체크·수치 잠금·차트·연재 자동 보완이 끝난 최종 제목·본문을 다시 검수해요. 본문이 같으면 앞선 요청 검수 결과를 재사용해요.
- 미반영, 심사 점수 하락, 새 치명 결함, 기존 통과 사실 검증의 실패, 새 코드 정적 검사 문제·작성 메모가 있으면 후보를 채택하지 않아요. 이전 원고·점수·검증 보고서·도판 경로를 유지하고 후보와 미채택 이유는 비공개로 보존해요.
- 미채택으로 최종 단계까지 가지 않는 경우에도 후보 판정 단계에서 남은 검증·심사 호출 사용량을 기록해요. 미채택 작업의 호출이 사용량 집계에서 빠지지 않게 해요.
- 점수 하락은 보수적인 자동 채택 차단 기준이에요. 모델 점수 자체는 흔들릴 수 있으며, 사람이 후보를 교열한 뒤 `--review-only`로 다시 심사하는 기존 경로는 유지해요.
- 저장 직전에 원고 행을 잠그고 제목·본문·기존 심사·관리자 지시가 그대로인지 확인해요. 다른 편집이 생겼으면 기존 원고 유지 처리도 그 편집을 덮어쓰지 않아요.
- 관리자 화면에서 요구별 반영 상태·근거·보류 사유·점수 비교와 미채택 보완본을 볼 수 있어요. 후보 본문은 HTML을 실행하지 않는 텍스트로 표시해요. 미완료 요청은 형식 예외 승인으로 우회하지 못해요.
- 일반 칼럼과 명시적인 관리자 지시가 있는 연재 재작성에 공통 적용했어요. 직접 교열본을 다시 쓰지 않는 `--review-only` 동작은 유지해요. 새 원고의 사람 승인 요건도 유지해요.

## 글쓰기 기준

독자가 해결할 질문과 답을 앞에 두고, 실제 변화 → 근거와 원리 → 구체적인 활용 → 반론·한계로 논지를 연결해요. 첫 문단을 시대 변화나 개념 정의로 채우지 않으며, 최근 발표일·조사 기준일·소프트웨어 버전을 구분해요. 실제로 확인하지 않은 현장 경험·실측·인터뷰를 만들지 않아요. 소제목·사례·표의 정보 가치를 높이고 중복·빈 도입·제작 메모를 줄여요. 부분 수정에서는 이 지침을 이유로 요청 밖 문단을 다시 쓰지 않아요.

기존 심층성·논리·가독성 심사에도 같은 관점을 전달하되, 재심에서 새 취향을 필수 수정으로 추가하지 않도록 했어요. 이 기준은 글의 품질 향상을 보장하는 성능 측정 결과가 아니에요.

2026-11-11에 확인한 1차 자료:

- [Anthropic: Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) — 필요한 맥락을 선별하고 구조화하는 원칙
- [Anthropic: Building effective agents](https://www.anthropic.com/research/building-effective-agents) — 명시적인 평가 기준과 피드백을 쓰는 evaluator–optimizer 패턴. 원문은 2024년 자료이며 최신 모델 기능 설명으로 확대하지 않아요.
- [Google: Creating helpful, reliable, people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) — 독자에게 유용한 독창적인 분석·근거, 유행만 쫓는 콘텐츠와 구분
- [ONS: Structuring content](https://service-manual.ons.gov.uk/content/writing-for-users/structuring-content) — 중요한 답을 앞에 두고 읽기 쉬운 문단·소제목으로 구성

## 검증과 범위

최종 코드의 `office`·`common` 회귀 검사 **704개, 실패 0, MySQL 환경 전용 3개 제외**였어요(`logs/lab-admin-revision-final-regression-20261111.log`). 요청별 검수·연재·도판 삭제 및 렌더 후 검수를 포함한 별도 검사 **37개도 실패·제외 없이 통과**했어요(`logs/lab-revision-visual-paths-20261111.log`). 이 37개에는 회귀 검사와 겹치는 항목이 있어 합산하지 않아요. 이전 관련 검사 61개도 통과했어요. Django check, `makemigrations --check --dry-run`, `git diff --check`도 정상이었어요.

요청 누락·중복 판정·최종 원고에 없는 완료 인용·문자열 true·부분 편집 불일치·임의 제목 변경·후처리의 수정 되돌림·점수 하락·새 사실 검증 실패·새 코드 오류·새 작성 메모·작업 도중 다른 편집을 검사했어요. 미채택 후보의 HTML이 관리자 화면에서 실행되지 않고 이스케이프되는 것과, 연재 후속 자동 수정이 요청을 되돌렸을 때 기준 원고가 유지되는 것도 확인했어요.

실제 Claude 구독의 작성·독립 검수 2회 호출로 복합 요청을 확인했어요. 도입 첫 문장 교체, 지정 문장 삭제, 제목·다른 절·참고 자료 보존을 코드로 대조했고 최종 검증 전 기준 원고가 덮어써지지 않은 것도 확인했어요. 결과는 `logs/private-lab/admin-revision-smoke-20261111/result.json`, 실행 로그는 `logs/lab-revision-subscription-smoke-20261111.log`예요. 외부 사실이 없는 편집 기능 예시이므로 새 글의 사실 정확성·점수 상승·전체 품질 개선의 실증으로 해석하지 않아요.

PC 1280px와 모바일 390px에서 관리자 결과 패널을 확인했어요. 모바일 User-Agent와 `force_version=mobile` 쿠키로 실제 모바일 템플릿 분기를 거쳤고 가로 넘침은 없었어요. 화면 자료는 운영 데이터가 아닌 fixture이며 스크린샷은 `scratchpad/lab-admin-revision/`에 있어요. fixture가 제공하지 않는 favicon·활동 폴링 URL의 404는 실제 관리자 서버 장애로 집계하지 않았어요.

운영 배포·재시작·운영 DB 마이그레이션 적용·원격 push는 하지 않았어요. DB 필드를 추가하지 않아 새 마이그레이션도 없어요. 이번 소스로 MySQL 동시성 검사를 새로 실행한 결과로 이전 버전의 38개 통과 기록을 대체하지 않아요.

비자명한 정책은 요청별 완료 근거, 최종 후처리 후 재검수, 점수 하락 시 원고 보존, 미채택 후보의 비공개 보관이에요. Claude 메모리에 남길 만한 결정이며 저장소 밖 메모리는 수정하지 않았어요.
