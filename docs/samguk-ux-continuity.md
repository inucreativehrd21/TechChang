# 삼국지 연속 플레이 UX 개선

## 설계 기준

게임의 주인공인 지도와 장수 초상을 크게 두고, 사용자가 고른 도시의 행동을 바로 옆에서 실행해요. 매번 읽어야 하는 상태는 상단 한 줄, 필요할 때 찾는 등용·전설·기록은 같은 명령 패널의 탭으로 모아요.

색은 premium.css의 인디고 #4f46e5, 잉크 #18181b, 본문 #3f3f46, 보조 #71717a, 경계 #e4e4e7, 바탕 #ffffff를 따르고 Pretendard를 유지해요. 큰 장식·새 폰트 대신 지도와 인물의 그림으로 게임의 개성을 드러내요. 텍스트는 왼쪽 정렬하고 수치·행동 비용을 구분해요.

```text
게임 제목·날짜                              장원 / 도감 / 객잔 / 순위
군령과 잔여량                 금 / 군량 / 점수                 정세
┌──────────────────────────┬──────────────────────┐
│                          │ 도시 | 등용 | 전설 | 기록 │
│      천하 지도             │ 선택 도시와 장수          │
│                          │ 내정 / 징병              │
│                          │ 출정·계략 조작            │
├──────────────────────────┤                        │
│ 바로 전 행동 결과           │ 오늘 판 마치기            │
└──────────────────────────┴──────────────────────┘
```

모바일은 지도 접기와 도시 선택을 제공하고 선택한 도시 한 곳을 표시해요. JS가 없으면 기존 도시 목록과 POST 폼이 그대로 동작해요. Bootstrap의 격자와 폼 의미는 활용하면서 반복되는 아웃라인 버튼·동일한 카드 묶음은 명령 패널 안의 명확한 위계로 정돈해요.

## 연속 동작

- 기존 POST 주소·입력 이름·CSRF·seq와 서버 판정을 보존해요. fetch는 같은 폼을 한 번 전송하고, 기존 redirect 뒤에 오는 서버 렌더 본문만 갱신해요.
- 선택 도시, 탭, 펼친 조작, 입력 중인 값, 패널·화면 스크롤을 보존해요. 지도 그림 DOM도 같은 판에서는 재사용해요.
- 전송 중 중복 제출을 막고 결과를 live region으로 안내해요. 실패 시 POST를 자동 재전송하지 않아요. 최신 상태를 GET으로 확인한 뒤 계속할 수 있게 해요.
- 새 CSRF/seq, 옵션 목록, 병력 상한과 버튼 가능 여부는 항상 새 서버 응답을 사용해요. 확인할 수 없는 결과를 화면이 추측하지 않아요.
- 하루 경계·로그인 만료·유효하지 않은 요청, JS 없는 기본 폼, PC/모바일, 연속 제출을 검증해요.

## 설계 검토

처음처럼 등용과 전설을 지도 밑의 긴 카드 목록으로 두면 지도와 조작이 분리되고 매번 스크롤해야 해요. 이 부분을 오른쪽 명령 패널로 옮겨 반복 행동이 한 자리에서 이어지게 했어요. 지도에 장식을 추가하는 대신 실제 선택 표시·최근 결과·조작의 유지에 초점을 맞춰요.

## 구현 결과

- 900px 이상에서는 지도·최근 행동과 명령 패널을 나란히 배치해요. 명령 패널만 내부 스크롤하므로 지도와 자원을 보면서 행동할 수 있어요.
- 모바일에서는 자원 표시를 상단에 고정하고, 지도 접기·도시 선택·4개 명령 탭을 제공해요. 도시 선택에 이름·소유 세력·점수를 모아 중복 제목을 줄였어요.
- 결과는 서버가 만든 최근 행동에 표시해요. 모바일에서 지도를 접어 최근 행동이 가려지면 별도 결과 알림을 보여줘요. 스크린 리더에는 live region으로 안내해요.
- 출정과 계략은 접이식 조작으로 분리하고, 군령·징병 금·실제 출정 비용을 표시해요. 오늘 판 마치기는 확인 대화상자를 거쳐요.
- 장원·객잔의 POST도 같은 방식으로 갱신해요. 페이지 이동 링크는 일반 탐색을 유지해요.

## 응답과 상태 보존 정책

`X-Samguk-Partial: 1` 요청에만 JSON 안의 서버 렌더 본문을 반환해요. 기존 POST → redirect → GET 흐름을 그대로 사용해요. 응답에는 `Vary: X-Samguk-Partial`을 붙이고, 부분 응답은 `Cache-Control: no-store`로 처리해요. 일반 요청과 JavaScript가 없는 폼은 전체 HTML 흐름을 사용해요.

선택 도시·탭·지도 접기·details·폼 초안·스크롤·포커스는 응답을 적용할 때 캡처해요. 같은 사용자와 같은 게임 날짜일 때만 복원하고, CSRF·seq·서버의 옵션·병력 상한은 새 응답을 사용해요. 자동 저장하는 개인정보 체크박스는 초안 복원에서 제외하여 서버 저장값을 표시해요. 연습 판의 최근 결과는 세션에만 저장하고 정식 일일 기록을 만들지 않아요.

중복 제출을 잠그고, 결과를 확인하지 못하면 POST를 자동으로 다시 보내지 않아요. 서버에서 이미 처리했을 가능성이 있으므로 GET으로 최신 상태를 확인한 뒤 조작을 풀어요. 로그인 만료 시 다시 로그인할 목적지는 행동 POST 주소가 아닌 현재 게임 GET 주소예요.

| 검증 | 결과 |
| --- | --- |
| Django 삼국지 관련 5개 테스트 모듈 | 80개 통과, 36.027초 |
| `manage.py check --settings=config.settings.local` | 오류 없음 |
| `node --check static/js/samguk.js` | 통과 |
| 실제 PC 연속 행동 | 전체 문서 요청 0회, 창·지도 DOM 유지, seq와 자원 갱신 |
| 도시·펼친 출정·병력 입력·장수 선택·스크롤 | 행동 후 유지 |
| 모바일 연속 행동 | 지도 접기·도시·스크롤 유지, 결과 알림 표시 |
| 빠른 중복 제출 | POST 1회만 전송 |
| 서버 처리 뒤 응답만 유실 | POST 재전송 없이 GET으로 seq 갱신 확인 |
| 로그인 만료·하루 경계·유효하지 않은 행동·CSRF | 오류 안내 및 서버 정책 유지 |
| 장원 장식·개인정보·객잔 영입·연습·판 종료 | 부분 갱신 및 서버 결과 확인 |
| JS 없는 기본 폼 | 정상 POST 및 전체 HTML fallback |
| PC 1366·1024·900px, 모바일 390·360px | 가로 넘침 없음, 탭 키보드 이동 확인 |

실제 브라우저 검증은 `preview_server.py`의 임시 메모리 DB에서 수행했어요. 운영 배포·원격 push·기존 DB 마이그레이션은 실행하지 않았어요. 최종 시각 확인 이후의 결과 알림 변경도 모바일 실제 행동과 JavaScript 문법 검사로 확인했어요.

## Claude 메모리에 남길 결정

부분 응답의 opt-in 헤더·Vary 계약, 응답 적용 시 UI 상태 복원, 권한·seq·CSRF는 서버값 사용, 결과 유실 시 GET 확인만 하고 POST 재전송 금지 정책을 유지해야 해요. 외부 메모리는 수정하지 않았어요.
