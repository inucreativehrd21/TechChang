# 관리자 대시보드 개편 · 게임 관리

2026-10-25 로컬 구현. 운영 배포·원격 push·운영 DB 마이그레이션은 하지 않았어요.

## 화면

- 공통 탐색: 대시보드 / 게임 / 사용자 / 포트폴리오 / 서버 / IP 차단 / 연구실.
- 대시보드, 사용자 목록·상세, 포트폴리오 승인, 서버 모니터·로그 뷰어, IP 차단, 연구실, OTP 인증 화면을 밝은 배경·인디고 강조·공통 글꼴로 통일했어요.
- 사용자 검색·등급 변경·활성화, 포트폴리오 승인·반려·회수, 서버 상태 조회·기존 조치, IP 등록·해제, 연구실 내부 6개 탭과 기존 폼을 유지했어요.
- 모바일에서는 탐색·표를 각 영역 안에서 가로 스크롤해요. 연구실 탭은 방향키·Home·End도 지원해요. 서버 자동 새로고침은 끌 수 있고 다른 탭을 보는 동안 멈춰요.
- 사용자 비밀번호 재설정과 프로필 저장을 분리했어요. 비밀번호만 바꿀 때 닉네임·관리자 권한을 지우던 기존 경로를 수정했어요.

## 게임 관리

주소: `/common/admin/games/`. 관리자 권한과 기존 IP 바인딩 OTP 인증을 모두 요구해요.

| 기능 | 키 | 필요한 게임 스키마 |
| --- | --- | --- |
| 시리즈 전광판 | `ROOKIE_SERIES_ENABLED` | `community.0053_liteseason_series` |
| 경기 환경·조건부 특성 | `ROOKIE_ENV_ENABLED` | `community.0054_liteseason_env` |
| 익스트림 공개 | `ROOKIE_EXTREME_ENABLED` | `community.0052_litecareer_mode` |
| 익스트림 관리자 검증 | `ROOKIE_EXTREME_PREVIEW` | `community.0052_litecareer_mode` |

각 기능은 **환경 설정 사용 / 켜기 / 끄기**로 조작해요. 기존 환경 변수 기본값은 유지하며, 저장된 DB 관리자 설정이 우선해요. 환경 설정 사용으로 돌리면 해당 덮어쓰기를 제거해요.

- 저장소는 `common.0017_game_controls`의 `GameControlState`와 `GameControlChange`예요. GET 조회는 설정 행을 생성하지 않아요.
- 설정 저장은 CSRF, 입력값·필수 마이그레이션 검사, 트랜잭션, 행 잠금, revision 비교를 거쳐요. 오래된 화면에서 저장하면 HTTP 409와 새로고침 안내를 보여 줘요.
- 실제 변경만 이력에 남기고 최근 20건을 표시해요. 변경한 관리자·시각·변경 전후 값을 기록해요.
- 재시작 없이 **다음 요청부터** 모든 워커가 DB 설정을 읽어요. 프로세스별 `LocMemCache`는 사용하지 않아요. 한 요청/시즌 처리 안에서는 스냅샷을 공유해 도중에 계산 기준이 바뀌지 않아요.
- 새 저장소 적용 전에는 기존 환경 설정을 사용해요. 게임 관리에서는 저장소·기능별 DB 준비 상태를 표시하고 준비되지 않은 기능을 켜지 못하게 해요.
- `GAME_CONTROLS_USE_DB=False`는 DB 없이 실행하는 순수 엔진 테스트의 격리용 설정이에요. 운영 기본값은 DB 사용이며 관리 화면에서 바꾸는 항목은 아니에요.

게임별 진행·완료·오늘 시작 수치, 변경 이력, 실제 게임과 장면 미리보기 바로가기를 제공해요. 미리보기 주소는 `/common/admin/games/preview/`이며 OTP로 보호돼요. 실제 선수·경기 기록을 만들지 않고 `DEBUG=False`에서도 사용할 수 있어요. 기존 공개 `/rookie/preview/`는 계속 DEBUG 전용이에요.

## 배포 시 유의할 점

코드와 정적 파일 외에 `common.0017_game_controls`를 적용해야 스위치를 저장할 수 있어요. 경기 환경을 켜기 전에는 `community.0054_liteseason_env`도 필요해요. 이번 작업은 마이그레이션 파일만 추가했으며 운영에는 적용하지 않았어요. 기존 환경 설정 또는 이전에 저장된 관리자 설정을 임의로 켜지 않아요.

연구실 수동 실행 버튼은 기존 CLI 백엔드 또는 이미 허용된 유료 API 설정에 맞춰 표시돼요. 새 API 호출·유료 허용·CLI fallback·서버 `crew_work` 실행을 추가하지 않았어요.

## 검증

- `py -3.10 -X utf8 manage.py test --noinput`: 전체 1,013개 정상 완료(1개 건너뜀). `manage.py check`와 마이그레이션 변경 검사도 통과했어요. Windows 콘솔 인코딩 오류를 피하려고 UTF-8 옵션을 사용했어요.
- 신규 관리 테스트 10개: 환경값 상속·DB 우선순위·변경 이력·동시 저장 충돌·마이그레이션 검사·요청 스냅샷·권한/OTP/IP/CSRF·비공개 미리보기·PC/모바일 템플릿·비밀번호 재설정 보존.
- PC 1440px / 모바일 UA 390px·320px의 9개 관리 화면에서 정상 응답·제목·JS 예외·페이지 가로 넘침을 확인했어요. 연구실 내부 6개 탭과 키보드 이동, 다른 IP의 OTP 인증 화면도 확인했어요.
- 별도 QA SQLite DB에서 브라우저로 스위치 켜기·저장·새로고침 유지·이력 생성·환경값 복원, 회원 등급 변경·활성화 확인/취소·복원을 확인했어요. 로컬 기본 DB나 운영 데이터는 사용하지 않았어요.
- 관리자 미리보기에서 환경·특성·시리즈 장면의 이미지 로드와 모바일 넘침, 특성 발견 즉시 재생·닫기를 확인했어요.
- 스크린샷: [게임 관리 PC](../scratchpad/admin-remake/games-desktop.png), [모바일](../scratchpad/admin-remake/games-mobile.png), [대시보드](../scratchpad/admin-remake/overview-desktop.png). 나머지 검증 이미지는 `scratchpad/admin-remake/`에 있어요. 검증 서버·브라우저는 종료하고 임시 DB와 인증 세션 파일은 삭제했어요.

메모리에 남길 결정: 게임 플래그는 이제 환경 변수만으로 판단하지 않고 DB 관리자 설정을 우선해요. `common.0017` 의존성과 OTP 미리보기 경로를 함께 기록하면 돼요. 외부 메모리는 수정하지 않았어요.
