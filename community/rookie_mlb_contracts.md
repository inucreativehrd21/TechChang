# MLB 계약 개편 · 2026-10-20

사용자 요청은 ‘기본 제안을 받으면 아무 손해가 없는 계약’에서 벗어나, 권리를 얻는 비용과 계약 뒤의 선수 생활을 연결하는 것이에요. 아래 확률·금액·진행 방식은 게임 밸런스예요. 실제 선수 계약 금액이나 실제 구단별 로스터 상황을 뜻하지 않아요.

## 계약서에서 따로 봐야 할 것

| 계약 선택 | 협상 위험 | 계약 뒤 영향 |
|---|---|---|
| 기본 제안 수락 | 성사 가능성이 높아요. | 기본 마이너 거부권·선수 옵트아웃이 없어요. MLB 입단 후에도 개막 로스터 경쟁에서 밀리면 트리플A로 갈 수 있어요. |
| 마이너 거부권 최후통첩 | 성사 확률 3~30%. 한 번 거절되면 바로 결렬돼요. | 성공하면 계약 기간 중 동의 없는 마이너행을 막아요. |
| 연봉 35% 양보 + 거부권 | 3~58%. 최후통첩보다 쉽지만 실패할 수 있어요. | 계약 기간 내내 낮아진 연봉을 받아요. 거부권은 같아요. |
| 연봉 20% 인상 | 예산·관심도에 따라 위험해져요. | 합의해야만 인상액이 계약에 들어가요. |
| 연봉 10% 양보 | 성사 가능성을 높여요. | 연봉만 낮아져요. 거부권을 얻지는 않아요. |
| 핵심 선수 기용 계획 | 감독 신뢰를 높이는 역할 협상이에요. | 주전 출전을 계약으로 강제하지 않아요. 부진하면 자리 경쟁에서 밀릴 수 있어요. |
| 첫 시즌 뒤 선수 옵트아웃 | 성사 확률 8~62%. | 잔여 계약이 있을 때 매 시즌 한 번 유지/시장 도전을 선택해요. 시장 도전은 남은 보장액을 포기해요. |

확률은 실력·인기·국제 평판·자기 관리·구단 관심도와 예산을 반영해요. 확률을 화면에 먼저 보여 줘요. 거절된 권리나 요구 연봉이 다음 수정 제안에 남지 않도록 했어요. 보통 최대 세 차례 조율하며, 최후통첩은 예외예요.

## 계약 뒤 실제 결과

새 MLB 계약의 개막 로스터 검토 확률은 `0.32 + (72 - OVR) × 0.055 + 제안에 저장된 구단 경쟁도 + (50 - 신뢰) × 0.002`를 4~85%로 제한해요. 같은 시즌에 새로고침하거나 훈련 선택을 반복해 다시 추첨하지 않아요. 실존 구단 선수 명단을 조회하는 기능은 아니에요.

거부권이 없으면 개막 로스터 탈락 시 트리플A로 내려가요. 시즌 중·시즌 말 강등 면담에서는 마이너행 수용 또는 에이전트를 통한 재고 요청을 할 수 있어요. 재고 요청은 실력·신뢰에 따른 5~60%의 호소이며, 권리는 아니에요.

거부권이 있으면 강등 통보에서 동의/거부를 선택해요. 거부하면 구단이 방출 대신 MLB 벤치·추격조 잔류를 택해요. 실제 경기 모형의 `bench`/`mop` 보직이 적용되어 타석·이닝, 성적·WAR·성장 기회가 줄 수 있어요. 정상적인 콜업·성적 경쟁은 계속 있어요. 거부권을 행사했다는 이유로 영구 능력치나 자기 관리를 깎지 않아요. 정식의 비활동 감쇠, 라이트의 보직 불화에 따른 강등도 거부권을 우회할 수 없어요. 라이트의 기존 방출→강제 은퇴 규칙은 진행 중인 새 MLB 계약에 적용하지 않아 보장액이 사라지는 것을 막아요. 마이너에서 트레이드되어도 같은 계약의 급여와 권리를 새 구단에 승계해요.

라이트는 6구간의 등록 비율로 스플릿 급여와 MLB 서비스타임을 계산해요. 예를 들어 MLB 연 60억/마이너 연 6천만원 계약에서 전후반기를 반씩 보내면 연봉은 30억 3천만원, MLB 서비스타임은 0.5시즌이에요. 출전이 없는 MLB 벤치도 MLB 등록 구간 급여를 받아요. 전액 보장 계약은 마이너 체류만으로 연봉이 줄지 않아요. 정산액은 실제 현금·통산 수입·소득세 계산으로 이어져요.

정식은 시즌당 28경기일을 1시즌으로 환산하고 MLB 경기 정산일의 등록과 급여 장부를 쌓아요. 벤치도 MLB 서비스타임, 마이너는 제외해요. **정식에는 원래 현금 경제가 없으므로 급여는 현금 상점과 연결하지 않고 경력 장부로만 표시해요.** 이 장부는 정산된 경기일의 기록이며 비활동 기간을 포함한 전체 지급 내역은 아니에요. 정식의 주된 계약 결과는 리그·출전·성장 경로예요.

이 개편에서 추적한 MLB 서비스타임이 5시즌이면 계약에 별도 문구가 없어도 동의권을 인정해요. 과거 저장 데이터의 전체 등록일은 없으므로 이전 MLB 경력을 임의로 역산하지 않아요.

옵트아웃으로 시장에 나가면 기존 계약을 먼저 지우고 남은 보장액을 포기한 기록을 남겨요. 관심 세 구단 가운데 한 곳을 골라 협상하고, 실패하면 희망 KBO 구단 퓨처스에서 다시 시작해요. 계약 만료도 새 제안을 받는 단계로 이어져, 무계약 상태에서 옛 MLB 구단의 자리를 자동 유지하지 않아요. KBO 퓨처스는 게임 진행을 위한 임시 복귀 경로이며 실제 MLB 규정이 아니에요.

## 실제 규정 참고와 근사 범위

- MLB 옵션과 베테랑 동의권을 참고했어요. 게임은 20일·10/15일 대기나 옵션 소진을 일 단위로 재현하지 않아요. [MLB 마이너 옵션 설명](https://www.mlb.com/glossary/transactions/minor-league-options)
- 스플릿은 MLB와 마이너의 급여를 따로 정해요. 게임은 등록 구간으로 안분해요. [MLB 스플릿 계약 설명](https://www.mlb.com/glossary/transactions/split-contract)
- 선수 옵트아웃을 협상 권리로 다뤄요. 게임의 행사 시점은 첫 시즌 뒤부터로 통일했어요. [MLBPA 단체협약](https://www.mlbplayers.com/_files/ugd/4d23dc_d6dfc2344d2042de973e37de62484da5.pdf)

40인 로스터, 실제 선수별 옵션 연도, DFA·웨이버와 타 구단 클레임, 구단 방출에 따른 잔여 보장액 정산, 연봉조정·서비스타임에 따른 FA 자격 전체는 구현 범위에 포함하지 않았어요. 이번 거부권 행사 후 구단 반응은 ‘방출 대신 벤치 보유’로 정했어요. 향후 DFA를 추가한다면 구단이 방출한 경우와 선수가 옵트아웃한 경우의 보장액 처리를 구분해야 해요.

## 저장 호환성과 Claude 메모리 기록 후보

- 공용 `rookie_contracts.py`와 기존 `career`/`flags` JSON을 사용해요. DB 마이그레이션은 없어요.
- 새 포스팅·MLB FA 협상 성공 계약은 `contract.version = 2`예요. `system`, `team`, `minor_veto`, `split`, `minor_annual`, `player_opt_out`, 기간과 경과 시즌을 저장해요.
- 기존 계약은 새 스플릿 급여·개막 강등 불이익을 소급 적용하지 않아요. 기존 진행 중 협상은 명시적 조건을 확인한 뒤 새 계약 형식으로 체결해요.
- 거부권 면담·옵트아웃도 HTTP 화면 식별자를 검증해 중복·오래된 제출을 거절해요.
- 정식은 마이너행 미결 상태를 `assignment_pending`으로 별도 보관해 일반 인터뷰보다 먼저 보여 줘요. 계약 만료 시장은 같은 계약에 한 번만 열어요.
- 로컬 미리보기: `?scene=negotiation`, `?scene=assignment`, `?scene=assignment&veto=0&split=1`, `?scene=optout`. 실제 선수 데이터는 바뀌지 않아요.

검증: 야구 관련 전체 239개 테스트 통과 후, 트레이드 권리 승계·기존 강제 방출 방지·정식 POST 정산·같은 시즌의 중복 강등 통보 방지를 추가로 확인했어요. 최종 계약·상호작용 회귀 테스트 49개, Django 검사와 변경 파일 공백 검사가 통과했어요. PC·모바일 화면에서 가로 넘침·JavaScript 오류가 없었고, 브라우저에서 최후통첩 즉시 결렬·거부권 행사·옵트아웃 결과를 확인했어요.
