# 야구게임 전체 흐름 검사 · 2026-10-21

사용자가 전체 흐름 검사 후 Git 푸시를 요청했어요. 원격은 `inucreativehrd21/TechChang`이며, 야구 변경만 별도 브랜치로 보존해요. 작업 폴더의 CSP·일정 앱·개인 설정 변경은 포함하지 않아요.

## 발견한 오류와 수정

라이트의 선발 수업·보직 전환·재계약 장면에 `event_id`가 없었어요. 규칙 함수를 직접 부르면 진행됐지만, 실제 화면의 POST는 식별자 검증에서 거절돼 같은 선택 화면에 남았어요. `decision_view()`가 저장된 장면 내용으로 안정적인 식별자를 만들도록 수정했어요. 기존 커리어도 다음 화면 조회부터 정상적인 식별자가 붙고, 다른 장면의 오래된 요청은 구분할 수 있어요.

브라우저에서 프로 입단 뒤에는 상점 계획과 시즌 훈련 계획이 같은 `data-rl-plan` 표식을 사용해 훈련 스크립트가 상점 폼을 잡는 문제도 발견했어요. 없는 훈련 요소의 `dataset`을 읽다가 중단돼 훈련 개수·이벤트 응답 안내가 작동하지 않았어요. 두 스크립트가 각각 자신의 폼만 선택하게 범위를 좁혔어요.

## 전체 흐름 검사

`community/test_rookie_flow.py`에서 임시 테스트 DB와 CSRF 검증을 사용하는 실제 뷰 요청으로 확인해요.

- 회원 타자(PC), 손님 타자(모바일), 회원 불펜(모바일), 손님 선발(PC)을 각각 생성하고, 훈련 계획·시즌 진행·중간 선택·드래프트·프로 커리어·은퇴·카드·전당까지 끝까지 진행해요.
- 손님 두 경로는 세 시즌 후 로그인해 같은 커리어가 계정으로 이관되고 계속 진행되는지도 확인해요.
- 정식은 리틀야구에 불펜 지망 선수로 입단한 뒤 실제 날짜를 하루씩 진행해 출석 TP·훈련·진학·드래프트·프로 활동·감독 면담·은퇴를 거쳐 기록·카드·리그·시상 페이지를 조회해요.
- 서버가 정상 요청에 경고를 내거나, 저장 상태가 진행되지 않거나, 은퇴까지 완료하지 못하면 검사를 실패시켜요.

검사 결과: 라이트 네 경로와 정식 한 경로가 모두 통과했어요. 자동화는 수십 년을 수초~수십초에 진행하므로, 이 검사에서는 단계마다 테스트 캐시를 초기화해 분당 요청 제한과 분리했어요. 실제 요청 제한 규칙은 변경하지 않았어요.

## 회귀 검사와 배포 범위

- 현재 작업 폴더의 Django 시스템 검사와 전체 테스트 772개가 실패 없이 완료됐어요(기존 조건부 생략 1개). 이는 신규 전체 흐름 검사 다섯 개를 추가하기 전 실행이에요.
- 추가로 라이트 전체 흐름 네 개와 정식 전체 흐름 한 개가 통과했어요.
- 푸시할 파일만 담은 별도 소스 복사본에서 **전체 763개 테스트가 모두 통과**했어요(생략 0개, 273.262초). 작업 폴더의 772개와 개수가 다른 것은 별도 CSP·일정 작업의 검사를 제외하고 새 흐름 검사 5개를 포함했기 때문이에요. Django 시스템 검사는 이상 없고 `makemigrations --check --dry-run`도 변경 없음을 확인했어요.
- 마지막 JavaScript 수정 뒤에는 라이트 전체 흐름·상점 관련 12개 검사도 추가로 통과했어요. PC·모바일 브라우저에서 훈련 0/2→2/2와 시작 버튼 활성화, 상점 합계 600만원 갱신, 두 폼의 독립 동작, 선발 수업·평가 결과 진행을 확인했어요. 수정 후 해당 흐름의 JavaScript 오류와 가로 넘침은 없었어요.
- 실제 로컬 DB와 운영 DB에 테스트 선수를 만들거나 마이그레이션을 적용하지 않아요. 브라우저 검증 서버도 별도 임시 DB를 사용해요.
- 기존 1,000회 밸런스 결과는 [요약](reports/rookie-balance-v2-summary.json)과 [압축 원본](reports/rookie-balance-v2-1000.json.gz)으로 함께 보존해요. 이번 수정은 HTTP 장면 식별자에 관한 것으로 경기·성장 수치는 바꾸지 않았어요.

Claude 메모리에는 ‘직접 엔진 호출만으로는 실제 폼의 식별자 누락을 잡을 수 없으므로 CSRF를 포함한 전체 요청 흐름 검사도 유지한다’는 결정을 인계할 만해요. 외부 메모리는 수정하지 않았어요.
